---
title: Receive webhooks
description: Deliver signed Metal lifecycle events to your systems with retries and redelivery.
---

Organization owners and admins can register webhook endpoints that receive signed HTTP deliveries
for Metal lifecycle events. Every delivery carries a stable event envelope, so consumers can
deduplicate on `event_id`.

## Event catalog

Endpoints subscribe to any subset of the public event catalog, or to every event when no filter is
selected:

- Organization and project lifecycle: `organization.created`, `organization.updated`,
  `organization.deleted`, `organization.provider_credentials.configured`,
  `organization.provider_credentials.rotated`, `organization.provider_credentials.removed`,
  `project.created`, `project.updated`, `project.deleted`
- Sandbox lifecycle: `sandbox.requested`, `sandbox.ready`, `sandbox.paused`, `sandbox.resumed`,
  `sandbox.attempt_started`, `sandbox.attempt_failed`, `sandbox.cost_updated`, `sandbox.failed`,
  `sandbox.deleted`
- Runtime: `process.queued`, `process.started`, `process.cancel_requested`, `process.completed`,
  `process.cancelled`, `process.failed`, `runtime_operation.completed`, `runtime_operation.failed`,
  `endpoint.created`, `endpoint.revoked`, `endpoint.expired`, `endpoint.failed`
- Billing: `billing.credits_purchased`, `billing.credits_granted`, `billing.usage_charged`,
  `billing.auto_topup_failed`, `billing.spend_limit_reached`
- Connectivity checks: `webhook.test`

Event payloads use the same redacted public envelope as the durable event history. Secret material
is never included.

## Verify signatures

Each delivery is an HTTP POST of the event envelope JSON with these headers:

- `metal-delivery-id`: the delivery identifier, stable across retries
- `metal-event-id`: the durable event identifier, stable across endpoints
- `metal-event-type`: the event type
- `metal-signature-timestamp`: Unix seconds when the request was signed
- `metal-signature`: `t=<timestamp>,v1=<hex HMAC-SHA256>`

The signature covers the exact request bytes as
`HMAC-SHA256(secret, "<timestamp>.<delivery_id>.<raw_body>")`. Reject requests older than five
minutes, compare digests in constant time, and scope verification per endpoint secret.

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

function verifyWebhook(request: Request, rawBody: string, secret: string): boolean {
  const deliveryId = request.headers.get("metal-delivery-id") ?? "";
  const header = request.headers.get("metal-signature") ?? "";
  const match = /(?:^|,)t=(\d+),v1=([0-9a-fA-F]+)(?:,|$)/.exec(header);
  if (!match) return false;
  const timestamp = match[1]!;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 5 * 60) return false;
  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${deliveryId}.${rawBody}`, "utf8")
    .digest("hex");
  return (
    match[2]!.length === expected.length &&
    timingSafeEqual(Buffer.from(match[2]!), Buffer.from(expected))
  );
}
```

## Retries and duplicates

Deliveries are at-least-once. Metal retries network failures, timeouts, HTTP 408, HTTP 429, and
5xx responses with exponential backoff and jitter, honoring a bounded `Retry-After` header. Most
other 4xx responses, including unknown event rejections, are terminal. Redirects are never
followed and fail terminally.

Deduplicate on `metal-event-id` per endpoint. Retries of one delivery reuse `metal-delivery-id`;
manual redelivery creates a fresh attempt of the same event. Expect duplicates after worker
restarts and redeliveries.

## Endpoint restrictions

Production endpoints must use public HTTPS URLs. URLs with embedded credentials, private,
link-local, or cloud metadata addresses are rejected at creation and revalidated on every attempt.
Non-production environments relax HTTPS and private-network rules so local tunnels can be tested.

Disabled endpoints stop receiving production deliveries. Deleting an endpoint stops deliveries
immediately and destroys its signing secret; delivery history is retained for audit.

## Secrets and rotation

The signing secret is generated server side and returned once when the endpoint is created or
rotated. Store it immediately; later reads expose only a prefix. Rotation installs the new secret
atomically and invalidates the previous secret immediately, so update consumers before rotating.
Use the test action after rotation to confirm the new secret verifies.

## Operations

Test sends use the same URL validation, signing, transport, and response limits as production and
persist a clearly marked `webhook.test` delivery with its HTTP result, latency, and timestamp.
The dashboard shows per-endpoint delivery history with attempt counts and sanitized errors.

For alerting, watch for endpoints whose recent deliveries stay in `retrying` or land in `failed`,
and for a growing backlog of `pending` deliveries. Query delivery history per endpoint and
redeliver terminal failures from the dashboard or the webhooks API.

See the webhooks endpoints in the API reference for request and response shapes.
